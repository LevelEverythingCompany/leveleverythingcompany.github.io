Field note 003 / October 25, 2026

One clip. One useful result.

WaveForgeVideo is a good example of the kind of question I like building around: can a familiar task take fewer steps? Here is a look from the task to the documented workflow.

This walkthrough uses the current project guide and repository screenshot. It is not a recorded export or a claim of a new device test.

1. The question

Sometimes I only need to keep part of a clip, rotate it, or convert it to a different format. That is a focused job. WaveForgeVideo puts those controls in one desktop window.

2. The build

The app is a front end for FFmpeg. It brings source information, trim points, still-frame previews, output presets, and export logs into the interface. The original media is the starting point; the export is a separate result.

3. Try a small example

  1. Use a copy of a short, non-private video that is longer than 20 seconds. Install FFmpeg separately and confirm the app finds it.
  2. Load the clip. For this example, set Trim start to 12.5 seconds and Trim end to 20 seconds.
  3. Check the START and END still frames. They show trim points; they are not video playback.
  4. Choose MP4 H.264 and Keep source resolution. Use Choose Output + Start and choose a new output filename.
  5. Open the finished file in a media player. Check that it contains the intended segment and that its picture and sound are as expected.

Expected result for this example: a clip of approximately 7.5 seconds. This is a worked example of the documented controls, not a measured result from a new test.

4. Where the rough edges matter

FFmpeg must be installed separately. Previews are still pictures. Trimming re-encodes the video and takes export time. This is a single-clip tool; it does not have a multi-clip editing timeline.

The guide also describes a fallback to software encoding if a hardware export fails, and per-export logs for investigating a problem. Those are useful parts of making a tool understandable when something goes wrong.

5. What I want to learn from you

Could you find the trim controls? Was the output what you intended? Did you understand the requirements before downloading? A clear report of where you got stuck gives me something concrete to improve.

Field note 001 / A new beginning

Why this place exists.

I used to think each new interest needed its own name and its own place. One for photos. Another for stories. One for coding. Another for an experiment that started at midnight and got completely out of control.

Now I'd rather have one home where the threads are allowed to cross.

That's what these field notes are for. Not every idea will be a masterpiece. But the process deserves a record: what I tried, what broke, what surprised me, and what someone else might be able to use.

If a question feels too weird to belong here, it's probably exactly the kind of question I want to investigate.

The WaveForgeVideo walkthrough above starts that record with a real interface, a documented task, and the limits that matter when trying it.

Field note 002 / October 24, 2026

The release is only the beginning.

A working app still needs a way for someone else to understand it. This workshop update adds screenshots from the project repositories, direct routes to app releases, and requirements beside each build.

That also means showing the rough edges. DualCast still needs more testing with two physical Bluetooth devices. The translator’s SteamVR and phone experiences need fuller acceptance testing. Lore’s site badges separate sourced history from uncertain claims, and its web atlas is still a beta.

The useful evidence lives with the code: setup instructions, verification notes, known limitations, and issue trackers. Those links now sit beside the download buttons, where they can help someone decide what to try.
